# AGENTS.md

Working guide for Claude Code and other AI coding agents in this
repository, following the cross-tool [AGENTS.md](https://agents.md)
convention. Human contributors should read `CONTRIBUTING.md` instead —
this file duplicates only what's necessary for an agent to be useful
without re-discovering the project structure each session.

Claude Code specifically loads this file via the `CLAUDE.md` stub at the
repo root (a one-line `@AGENTS.md` import) — edit this file, not that one.

## TL;DR

This is **EPaper**, a vanilla web component library (70 source files, 95 registered Custom Elements)
optimized for e-paper displays. It is **not Lit-based** — Lit is only a
Storybook devDependency. Components extend `HTMLElement` directly or
`BaseFormControl<T>` for form controls. Light DOM only, no Shadow DOM.
No animations, no `:hover`.

## Repository layout

```

    __tests__/        7 suites (cleanup, form-association, reactivity, security,
                      data-display, new-components, screenshots)
  core/               dom.ts, base-form-control.ts, icons.ts, date.ts, types.ts
  styles/             tokens.css → base.css → components.css (cascade order matters)
  stories/            Storybook docs (composite/, display/, inputs/, layout/, navigation/, primitives/, typography/)
  demo/               Local dev demo (not shipped)
  index.ts            Barrel export — register every component as a side-effect import
scripts/
  build-css.mjs       PostCSS + cssnano pipeline
  gen-tag-map.mjs     Emits dist/elements.d.ts (HTMLElementTagNameMap augmentation)
.github/workflows/    ci.yml, deploy.yml, release.yml
dist/                 Build output. Never edit. Generated by `npm run build`.
reports/              CI artifacts. Gitignored. Never commit.
sample-app/           Validates README.md's runtime + TS claims against dist/. Not shipped.
```

## Most-touched files (in order of likelihood)

1. `src/components/<name>.ts` — adding a component or fixing a bug
2. `src/styles/components.css` — styling matches the component file
3. `src/stories/<group>/<Name>.stories.ts` — every component has one
4. `src/components/__tests__/*.test.ts` — add to existing suite, don't fragment
5. `src/core/dom.ts` — only when introducing a cross-cutting helper

## Hard rules (do not break)

1. **Use `esc()`** from `core/dom.ts` for every interpolated string.
   Skipping this is an XSS vector. Tests will catch you.
2. **Never use `attachShadow`.** Light DOM only. Style via `components.css`.
3. **No animations or transitions.** `base.css` resets them globally inside
   `.ink-page`. Adding any keyframes/transitions reverts the e-paper
   guarantee.
4. **No `:hover` rules.** Use `:focus-visible`, `[aria-selected]`,
   `[aria-checked]`, `[data-active]` instead.
5. **Form controls extend `BaseFormControl<T>`** and implement
   `serialize(v: T)` and `parse(s: string)`. Skipping this breaks
   `<form>` participation, BFCache restore, and the test suite.
6. **Global listeners must use `onGlobal(this, target, type, fn)`** from
   `core/dom.ts` and tear down via `runCleanups(this)` in
   `disconnectedCallback`. Anonymous `document.addEventListener` calls leak
   on every re-mount.
7. **Surgical updates only.** Use `patchText` / `patchAttr` /
   `patchBoolAttr` / `patchClassModifier`. Do not replace subtrees with
   `innerHTML` reassignment after the initial render — it forces a full
   GC16 EPDC waveform.
8. **JSDoc is required** with `@summary`, `@since`, `@attr`, `@fires`,
   `@slot`, `@example`. The Custom Elements Manifest analyzer reads it;
   without JSDoc there is no IDE autocomplete. Use the first public release
   version, e.g. `@since v1.0.1` or `@since v1.1.0`, and check the git tag
   history before claiming a newer version.
9. **TypeScript is strict.** No `any` outside escape hatches. The CI gate
   is `npm run lint:check` (`--max-warnings=0`). Don't add ESLint disables
   without a comment.
10. **Don't bypass the cleanup contract.** If a component opens a popover,
    a calendar grid, a dropdown — register every `document` listener with
    `onGlobal` so leaving the page doesn't leak.

## Adding a component (skeleton)

```ts
import { define, esc } from '../core/dom';

/**
 * @summary Short description.
 * @since v1.0.1
 * @attr {string} [foo] - Description.
 * @fires {CustomEvent<{value: string}>} e-change - Description.
 * @slot - Default slot description.
 * @example <e-foo></e-foo>
 */
export class EFoo extends HTMLElement {
  static observedAttributes = ['foo'];
  private _wired = false;

  connectedCallback() {
    if (this._wired) return;
    this._wired = true;
    this.innerHTML = `<span class="ink-foo">${esc(this.getAttribute('foo') ?? '')}</span>`;
  }

  attributeChangedCallback(_n: string, _o: string | null, _v: string | null) {
    if (!this._wired) return;
    // surgical patch only
  }
}

define('e-foo', EFoo);
```

Then:

1. Export from `src/index.ts`
2. Add a Storybook story in `src/stories/<group>/<Foo>.stories.ts`
3. Add styles in `src/styles/components.css` (search for the section
   matching the component group)
4. Add an entry to one of the cross-cutting test suites if applicable
5. Add a sub-path entry in `package.json` `exports` (alphabetically)

Or read `.agents/new-component.md`, which walks all five steps for you in
detail and links back here for the rules behind them.

## Event detail conventions

Default: `{ value: T }`. Known exceptions to be aware of (do not
"fix" without alignment — they are V1.0 contract):

- `e-checkbox`, `e-toggle` → `{ checked: boolean }`
- `e-upload` → `{ files: File[] }`
- `e-dropdown` → `{ index: number }` (event name `e-select`, not `e-change`)
- `e-button` → `{ originalEvent: MouseEvent }` (event name `e-click`)
- `e-form` → `{ form: HTMLFormElement }` (event name `e-submit`)

If you write a new component, use `{ value: T }` and `e-change` unless
there is a specific reason not to.

## Commands

```sh
npm run dev          # Vite demo at localhost:8085
npm run storybook    # Storybook at localhost:6006
npm test             # Vitest watch (browser mode, Playwright)
npm run test:ci      # Vitest run-once (CI)
npm run test:refresh # Mutation / node-churn / dirty-area budgets
npm run test:coverage:ci  # Vitest run-once + coverage + Sonar reports
npm run type-check   # tsc --noEmit, must be clean
npm run lint:check   # ESLint, max-warnings=0
npm run format:check # Prettier check
npm run build        # Vite + CSS + tsc + CEM analyze + tag-map gen
npm run size         # size-limit check (40 KB barrel, 6 KB button, 8 KB input)
```

CI runs all of the above on every PR (`.github/workflows/ci.yml`).
`prepublishOnly` runs `lint:check + type-check + build` before any publish.

## Releasing

`.github/workflows/release.yml` owns both npm channels:

- **`dev`** — every green CI run on `main` publishes
  `<next-patch>-dev.<run number>` under the `dev` dist-tag. Nothing to do
  by hand; `package.json` `version` is stamped in CI only, never committed.
- **`latest`** — pushing a `v*` tag runs four gated stages: `guard`
  (tag equals `v<package.json version>`, fails in seconds otherwise),
  `checks` (calls `ci.yml` as a reusable workflow — do not duplicate the
  gate here), `release` (npm publish + GitHub Release from the matching
  `CHANGELOG.md` section), and `update` (`smoke` installs the published
  version from the registry and registers it in jsdom via
  `scripts/smoke-test.mjs`, `deploy` calls `deploy.yml` for the tagged
  source). Tags with a prerelease part (`v1.1.0-rc.1`) go to `next`.

**`main` is protected** by a ruleset (`Baseline`): pull request required
(0 approvals), no force-push, no deletion, and no bypass actors. Direct
pushes fail — every change, including a version bump, goes through a PR.
Tags are not covered by the ruleset and can be pushed directly.

Cutting a release: move `[Unreleased]` entries into a
`## [x.y.z] — YYYY-MM-DD` section, then on a release branch run
`npm run bump-version -- patch|minor|major` (bumps, builds, commits; it
skips tagging off `main` and prints the remaining steps). Merge the PR
**with a merge commit** — squash or rebase would rewrite the bump commit
and strand the tag — then tag the merged commit on `main` and push the tag.

## Common gotchas

- **`useDefineForClassFields: false`** is set in `tsconfig.json` because
  Custom Element constructors must not assign properties before
  `super()` runs — class fields would do exactly that.
- **`exactOptionalPropertyTypes: true`** is on — passing `undefined`
  explicitly is a type error where the property is optional. Use
  conditional spread or omit the key.
- **`reports/` is gitignored** but tests sometimes write into it. If
  `git status` shows it, it is a misconfiguration — do not commit it.
- **`coverage.include` in `vitest.config.ts` and `sonar.coverage.exclusions`
  in `sonar-project.properties` are one setting in two files.** Sonar reads
  a source file with no lcov entry as 0% covered, not as unmeasured, so a
  path outside the Vitest include set must be excluded on the Sonar side
  too. Change one, change the other.
- **There is one test runner, not two.** Playwright is Vitest's browser
  provider, not a separate suite. Both Vitest projects (`unit`, `storybook`)
  run in a single `vitest run` and V8 merges their coverage into one
  `lcov.info` — there is nothing to combine afterwards.
- **CSS imports use sub-paths**: `@marcomattes/epaper-components/styles/tokens.css`
  resolves to `src/styles/tokens.css` via the exports map. The
  `sideEffects` array intentionally lists `./src/styles/*.css` for this
  reason — those files ARE shipped (see `files` array).
- **The library is vanilla, not Lit.** Lit is a `devDependency` for
  Storybook templating only. Never import `lit` from a
  `src/components/*.ts` file. The `"lit"` `package.json` keyword was
  removed in V1.0.0.
- **`LICENSE`, `CHANGELOG.md` exist at root since V1.0.0** and are
  shipped via the `files` array. Update `CHANGELOG.md` in the same PR
  as any user-visible change.
- **Storybook stories use the Lit `html` template tag** — that is the
  _only_ place Lit appears at runtime, and only in dev.

## Files NOT to touch without asking

- `package.json` `version` — bumped only by release process
- `package.json` `exports` — auto-aligned with `src/components/*.ts`
- `dist/**/*` — build output, always overwritten
- `.github/workflows/release.yml` — publish gate (`dev` on main, `latest` on
  `v*` tags). The **filename is load-bearing**: npm Trusted Publishing binds
  one workflow file per package, so renaming it or moving a publish step into
  a second workflow breaks authentication
- `custom-elements-manifest.config.mjs` — has a custom `localDefinePlugin`
  that detects `define()` calls (because the project is not Lit-based);
  any change risks losing IDE autocomplete
